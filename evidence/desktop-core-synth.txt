==================================================================
2. Three variants, and why only one of them is right
==================================================================

The cell library is passed to read_slang with -v, which the front-end
documents as "separate compilation units where modules are not
automatically instantiated".  That makes every primitive the DESIGN
instantiates disappear unless it is also named as --blackboxed-module.

  variant                                         cells   PLL CLKDIV  OSER10  gate
  primitives blackboxed, stock synth_gowin         8585     3      1       3  PASS
  primitives dropped, stock synth_gowin              36     0      0       0  FAIL
  primitives dropped, no -undriven                 7147     0      0       0  FAIL

Row 1 is the design.  Row 3 looks like a success -- 7147 cells, a
plausible histogram -- and has no clock generation and no TMDS
serializer in it at all: no PLL, no CLKDIV, no OSER10.  Row 2 is what
stock synth_gowin makes of row 3's netlist.  Nothing in a log
distinguishes row 1 from row 3 except knowing to count the primitives.

3. The check that now catches it
==================================================================

A blackbox instance drives the nets its output ports touch.  Drop the
instance and the nets remain, undriven, and yosys's check pass says so.
So scripts/synth-desktop.sh looks for driver-less wires whose name ends
in an output pin of one of the blackboxed primitives -- and fails the
build, deleting the netlist.  Against row 3 it names what went missing:

  ERROR: 31 output(s) of instantiated cell-library primitives are driver-less --

==================================================================
4. The road not taken (kept because it is the instructive part)
==================================================================

Before the -v behaviour was understood, the 7,147-cell netlist looked
like the answer and its 36-cell sibling looked like the bug.  The
diagnosis built on that was: 'opt -undriven in synth_gowin's map_ffram
section deletes the design, because the PLL outputs are legitimately
driver-less at synthesis time; run the pass chain with -undriven
omitted.'  The bisect that supported it, stopping the flow just before
each pass:

  -                  rc=0   cells=6927   submodules=1      total=6928
  coarse             rc=0   cells=6927   submodules=1      total=6928
  map_ram            rc=0   cells=1869   submodules=0      total=1869
  map_ffram          rc=0   cells=1931   submodules=0      total=1931
  map_gates          rc=0   cells=17     submodules=0      total=17
  map_ffs            rc=0   cells=50     submodules=0      total=50
  map_luts           rc=0   cells=34     submodules=0      total=34
  check              rc=0   cells=36     submodules=0      total=36
  vout               rc=0   cells=36     submodules=0      total=36

  (the fall at 'coarse' is memory inference -- 17 inferred memories
   becoming BSRAM -- and is expected.  The fall from 1931 to 17 across
   map_ffram is real, and is exactly opt -undriven doing its job.)

The retraction: with the primitives present, opt -undriven has nothing
to remove -- their outputs have a driver -- and the stock pass chain
runs to completion unmodified.  The flags were never the problem.  The
netlist they were deleting was a netlist with no PLLs in it, which is
a netlist that should be deleted.  The hand-rolled pass chain was
treating a symptom by stopping the tool from noticing it.
