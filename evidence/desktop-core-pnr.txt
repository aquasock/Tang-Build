==================================================================
3. Why there is no PLL to place
==================================================================

The clock structures in the published device databases:

  device         pad_pll   hclk_pips   io2hclk   hclk_div2 
  GW5A-25A       25        247         4         4         
  GW5AST-138C    0         0           0         0         
  GW5AT-60B      0         0           0         0         

  (read out of apycula/*.msgpack.xz with msgpack + lzma)

apicula's chipdb generator, chipdb.py:
  - _pll_pads has entries for GW1N-1/-4/-9/-9C, GW1NS-4, GW1NZ-1,
    GW2A-18/-18C and GW5A-25A.  There is no GW5AST-138C entry, so
    pll_pads() returns immediately and dev.pad_pll stays empty.
  - set_chip_flags gives HAS_5A_HCLK to GW5A-25A only; GW5AST-138C gets
    HAS_PINCFG, HAS_DFF67, HAS_CIN_MUX, NEED_BSRAM_RESET_FIX,
    NEED_CFGPINS_INVERSION, HAS_5A_DSP -- and no clock flag.
  - gowin_pll.py, the PLL parameter helper, covers devices up to
    'GW5A-25 ES'.

nextpnr's generator (himbaechel/uarch/gowin/gowin_arch_gen.py) builds its
5A HCLK/PLL machinery from those tables:
    if "HAS_5A_HCLK" in db.chip_flags:
        chip_flags |= CHIP_HAS_5A_HCLK;
so no flags and no pad table means no PLL bel.
